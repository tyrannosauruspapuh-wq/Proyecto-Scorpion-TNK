Bunos días. Dentro del desarrollo de este proyecto desempeñé el rol de Responsable de Integración y Verificación de Sistemas, una función fundamental para asegurar la correcta interacción entre los diferentes componentes de hardware y software que conformaban la arquitectura del sistema. Mi principal responsabilidad consistió en garantizar que el software de control ejecutado en el microcontrolador ESP32 pudiera comunicarse de manera eficiente, confiable y libre de errores con la arquitectura digital implementada en la FPGA Tang Nano 9K. Debido a que ambos dispositivos operan bajo principios de funcionamiento distintos, siendo el ESP32 un sistema basado en ejecución secuencial de software y la FPGA una plataforma de lógica programable basada en hardware concurrente, fue necesario diseñar y verificar cuidadosamente los mecanismos de comunicación para asegurar un intercambio de información robusto mediante la interfaz UART, evitando pérdidas de datos, errores de sincronización o comportamientos inesperados durante la operación del sistema.

Con el propósito de realizar una validación ordenada y eficiente, el proceso de integración y verificación fue dividido en tres etapas principales siguiendo principios de diseño modular. Esta metodología permitió analizar y validar cada subsistema de forma independiente antes de proceder a su integración completa, facilitando la detección y corrección de errores en etapas tempranas del desarrollo.

La primera etapa estuvo enfocada en las pruebas unitarias de software y la simulación de hardware. Antes de interconectar físicamente los dispositivos, se realizó una validación individual de cada componente para comprobar su correcto funcionamiento. En el caso del ESP32, se ejecutaron pruebas de comunicación utilizando el entorno de desarrollo Thonny. Para ello se implementó una prueba de Loopback físico, conectando directamente el pin de transmisión (TX) con el pin de recepción (RX), lo que permitió verificar que los datos enviados por el microcontrolador eran recibidos correctamente por él mismo. Durante estas pruebas se comprobó la transmisión adecuada de los comandos codificados en formato hexadecimal, utilizados posteriormente para controlar el movimiento del sistema, como el byte 0x01 destinado a la orden de avance y el byte 0x05 correspondiente a la instrucción de detención. Esta fase permitió confirmar la estabilidad del buffer de transmisión y la correcta configuración del módulo UART del ESP32.

Paralelamente, se llevaron a cabo las pruebas correspondientes al diseño implementado en la FPGA Tang Nano 9K. Para ello se utilizó un banco de pruebas o testbench dentro del entorno de simulación, donde se evaluó el comportamiento de la máquina de estados encargada de recibir y decodificar la información serial proveniente del ESP32. Se generaron secuencias ideales de bits simulando transmisiones UART a una velocidad de 9600 baudios, calculada a partir del reloj interno de 27 MHz disponible en la FPGA. Gracias a estas simulaciones fue posible validar el correcto funcionamiento de la lógica de recepción, la detección de bits de inicio y parada, así como el almacenamiento y procesamiento de los datos recibidos antes de proceder a las pruebas físicas.

La segunda etapa correspondió a la integración física de ambos dispositivos y representó el desafío técnico más importante del proyecto. Aunque los subsistemas funcionaban correctamente de manera independiente, durante las primeras pruebas de integración se observó que los motores no respondían a los comandos enviados desde el control inalámbrico. Este comportamiento evidenció la presencia de problemas que no podían detectarse en las simulaciones ideales y que surgían únicamente al interactuar con hardware real. Para identificar el origen de la falla se realizó un proceso sistemático de diagnóstico utilizando herramientas de instrumentación y monitoreo de señales.

Durante este análisis se detectaron dos problemas críticos. El primero estaba relacionado con el desfase de reloj y los fenómenos de metaestabilidad. Debido a que el ESP32 y la FPGA operan con relojes completamente independientes, las transiciones de la señal serial podían ser capturadas por la lógica secuencial de la FPGA en momentos no adecuados, generando estados indeterminados o errores de lectura. Para solucionar este problema se implementó una estructura de sincronización compuesta por tres etapas consecutivas de registros dentro del código Verilog. Esta técnica permitió estabilizar la señal proveniente del pin RX antes de que ingresara a la lógica principal del receptor UART, reduciendo significativamente la probabilidad de errores causados por metaestabilidad y mejorando la confiabilidad general del sistema.

El segundo problema detectado fue la ausencia de una referencia eléctrica común entre los dispositivos. Inicialmente, la señal recibida por la FPGA presentaba comportamientos erráticos debido a que el pin RX interpretaba fluctuaciones eléctricas y ruido como información válida. Después de analizar las conexiones se determinó que el sistema carecía de una tierra compartida entre todos los módulos. La solución consistió en unificar las líneas de tierra o GND del ESP32, la FPGA Tang Nano 9K y el controlador de motores TB6612FNG, estableciendo una referencia eléctrica común para todo el sistema. Una vez implementada esta corrección, la comunicación serial se estabilizó y los comandos comenzaron a ser interpretados correctamente por la FPGA.

La tercera etapa estuvo dedicada a la verificación del sistema de seguridad basado en el sensor ultrasónico HC-SR04, denominado dentro del proyecto como escudo de emergencia ultrasónico. Esta funcionalidad tenía como objetivo evitar colisiones durante la operación del vehículo robótico mediante la detección automática de obstáculos cercanos. Para validar este subsistema se realizaron pruebas en tiempo real sobre el módulo ultrasonic_detector implementado en Verilog. Durante este proceso se calibraron los contadores internos encargados de medir el ancho del pulso generado por la señal Echo del sensor, ya que este parámetro es directamente proporcional a la distancia medida.

Las pruebas permitieron comprobar que el sistema reaccionaba adecuadamente cuando un objeto ingresaba dentro de la distancia crítica previamente establecida. En dichas condiciones, el módulo ultrasónico generaba una interrupción de hardware con máxima prioridad dentro de la lógica secuencial del sistema. Esta interrupción forzaba inmediatamente un estado de parada en los registros de control de dirección de los motores, específicamente en las señales AIN1 y BIN1 del controlador TB6612FNG. Como resultado, el vehículo detenía su movimiento de forma instantánea, incluso si en ese mismo momento el ESP32 continuaba transmitiendo comandos de avance a través de la interfaz UART. Este comportamiento confirmó que el mecanismo de seguridad tenía prioridad absoluta sobre las órdenes de movimiento, garantizando así una operación más segura y confiable.

Como conclusión de esta experiencia, una de las lecciones más importantes aprendidas durante el desarrollo fue comprender que las simulaciones digitales representan únicamente un entorno ideal de funcionamiento. En la práctica, los sistemas embebidos están expuestos a múltiples factores físicos como ruido eléctrico, interferencias electromagnéticas, rebotes de señal, diferencias temporales entre relojes y variaciones propias de los dispositivos electrónicos. Estos fenómenos pueden provocar fallos que no son evidentes durante la etapa de simulación. Por esta razón, para futuros proyectos que involucren comunicación serial entre microcontroladores y FPGAs, se recomienda incorporar desde las primeras fases de diseño mecanismos adicionales de robustez, tales como verificación de paridad, detección de errores de transmisión, protocolos de control de flujo y estrategias de validación de datos. Asimismo, resulta fundamental mantener un adecuado aislamiento entre las etapas de potencia y las etapas lógicas del sistema para minimizar interferencias y garantizar una operación estable, segura y confiable en aplicaciones reales.
